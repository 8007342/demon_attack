# Asset pipelines

How the shipping art is produced and how to regenerate it. Each section owns its own family of assets; research notes on models, licences and consistency techniques live in [asset-pipeline/](asset-pipeline/README.md).

## Backgrounds (flyover parallax)

The oblique 3/4 flyover backgrounds (see "Backgrounds: oblique flyover parallax" in
[style-guide.md](style-guide.md)) are generated by a reproducible local ComfyUI
pipeline. Every input is committed; the GPU stage is deterministic for a fixed
ComfyUI build, model set and seed, and every later stage is deterministic
integer/NumPy work.

### Layout

| Path | Role |
| --- | --- |
| `art/families/flyover-backgrounds.json` | The family spec: per-sector prompts for the three strip layers, props, five routes × two landmarks, two creature species; seeds; strip/sprite sizes; per-layer luminance caps, widths and parallax speeds. |
| `art/workflows/backgrounds/strip-sheet.json` | API-format workflow for terrain strips: SDXL base + pixel-art-xl LoRA img2img from a layout sheet (`$init_image`, KSampler `$strength`), then an in-graph **roll by half height** (two `ImageCrop` + two `ImageCompositeMasked`) and a masked repaint of the middle band (`$mask`, `SetLatentNoiseMask`). The saved image therefore tiles vertically with no seam. |
| `art/workflows/backgrounds/sprite-transparent.json` | Transparent sprites (landmarks, props, creature poses): SDXL base + pixel-art-xl + LayerDiffuse conv injection; saves the RGB (`10_…`) and the decoded alpha (`12_…`) separately. |
| `art/workflows/backgrounds/txt2img-pixel.json` | Plain 512×1536 txt2img probe used to tune prompts. |
| `art/palettes/flyover-<sector>.json` | Bounded palettes (43 colours) median-cut from each painted sector sky, so generated layers keep that world's identity. |
| `art/families/flyover-runs.json` | Provenance of every ingested run: workflow, prompt, negative prompt, seeds, strength, models and SHA-256 of each raw output. |
| `tools/flyover_assets.py` | The driver (below). |
| `assets/images/flyover-<sector>.png` | Per-sector strip atlas, 384×576: rows mid/near/ground; columns three left-bank variants then their mirrors for the right bank. Logical pixels, drawn 2× with `FilterQuality.none`. |
| `assets/images/flyover-props.png` | Shelf-packed props and route landmarks for all sectors. |
| `assets/images/flyover-creatures.png` | One row per species: 8 frames (walk/crawl 0–3, duck 4–5, burrow 6–7) and the same 8 mirrored. |
| `lib/game/flyover_atlas.dart` | Generated metadata: sprite rects, creature rows, layer speeds and the per-row bank edge of every strip (used to place landmarks and keep creatures on the banks). Never edit by hand. |
| `art/contact/flyover-contact.png` | Contact sheet of every shipped strip (tiled twice to show the seam), sprite and creature frame. |

### Rerunning

```bash
# Keep the venv and raw generations OFF the checkout (the forge's /home/forge/src is a small tmpfs).
python3 -m venv $SCRATCH/asset-venv && $SCRATCH/asset-venv/bin/pip install pillow numpy
PY=$SCRATCH/asset-venv/bin/python
export FLYOVER_RAW=$SCRATCH/flyover-raw   # ingest copies raws here (default .cache/flyover-raw)
$PY tools/flyover_assets.py palettes   # sector palettes from the paintings
$PY tools/flyover_assets.py layouts    # img2img layout sheets + seam mask -> /work/tmp/imagegen/flyover/inputs
$PY tools/flyover_assets.py jobs       # 90 jobs -> /work/tmp/imagegen/flyover/jobs.json
# GPU stage, either:
$PY tools/flyover_assets.py run        # direct ComfyUI HTTP backend (COMFY_URL, default http://studio:8188)
#   (--only strip/,landmark/krybor limits the jobs; outputs land in /work/tmp/imagegen/flyover/http)
# or run each job through studio.run_workflow with the same workflow, inputs,
# strength and overrides, and save {job id: [output paths]} as results.json.
$PY tools/flyover_assets.py ingest [--results results.json]   # copy raws to $FLYOVER_RAW, record provenance
$PY tools/flyover_assets.py pack       # process + atlases + Dart metadata + contact sheet
flutter test test/flyover_background_test.dart test/sector_background_test.dart
```

`studio.run_workflow` resolves workflow paths against the project checkout, so
from a worktree pass the worktree-relative path. The HTTP backend binds the same
placeholders (`$prompt`, `$negative_prompt`, `$seed`, `$strength`, `$init_image`,
`$mask`, and `$node:<id>.<input>` overrides) the studio tool does.

### Processing stages (`pack`)

1. **Layouts.** Each strip sheet holds three 64×192-logical left banks (8 px per
   logical pixel). A seeded, vertically periodic contour (sum of integer-period
   sines plus promontories, snapped to 2 px terraces) defines each bank; its
   interior is filled with texture cut from the sector painting's horizon or
   foreground band, cliff faces below protrusions are darkened. img2img at
   strength 0.8 turns this into canyon-rim terrain with 3/4 cliff walls.
2. **Strips.** The rolled seamless sheet is box-downscaled to logical size,
   un-rolled, brightness-normalised under the layer's luminance cap (mid 0.13,
   near 0.18, ground 0.23) and snapped to the sector palette restricted to
   colours under that cap. Alpha follows the generated cliffs (non-void pixels)
   inside a dilated layout, is filled in the layout interior, and keeps only
   pixels connected to the outer screen edge; a one-pixel lit lip marks the drop.
   The final per-row edge is exported for runtime placement.
3. **Sprites.** LayerDiffuse alpha → bbox crop → box downscale to the spec's
   logical height (max widths keep the lane clear) → palette quantise under a
   cap (landmarks 0.40, props 0.34, creatures 0.36) and a chroma cap (creatures 0.28) (saturated warm colours are reserved for hostile fire) → binary alpha → despeckle; creatures get a one-pixel outline in the darkest palette colour.
4. **Creatures.** One generated pose per species becomes eight discrete frames
   on the logical grid: a four-frame walk (legs alternate, body bobs), crawl
   (one-pixel peristaltic column ripple) or burrow gait; two duck frames
   (flattened, darkened); two burrow frames (sinking into a dirt mound).
5. **Pack.** Strip atlases with mirrored right banks, a shelf-packed sprite
   atlas, a creature atlas with mirrored frames, the generated Dart metadata and
   the contact sheet. Total new asset weight is well under 0.5 MB.

### Runtime contract

`lib/game/flyover_background.dart` draws, per sector, three `drawAtlas` strip
batches (mid 0.2×, near 0.6×, ground 1.0×) plus one batch each for near
landmarks, ground props and creatures. Strip variants come from a no-repeat
seeded sequence per layer and side; landmarks/props/creatures are placed per
fixed-length segment from stateless seeded hashes, so any flight distance draws
the same picture on every device. Adding a sector or route means adding spec
entries, rerunning the pipeline and nothing else in Dart.

## Sprites

Combat creatures, sentinels, the carrier, the player ship, its cannons, muzzle flashes and every projectile. The contract (layouts, palette, timings) is [sprite-atlas.md](sprite-atlas.md); the visual rules are in [style-guide.md](style-guide.md#64-grid-detail-and-animation).

### Principle

Silhouettes, poses, armour, insignia, weapon mounts and effects are **authored deterministically** in Python on the logical grid (`tools/sprite_kit.py` + four generators), because eight-pose articulated strokes, molts, death sequences and recoil frames must stay aligned pixel for pixel across hundreds of frames. ComfyUI contributes **keyframe concept and shading detail**: renders are finished onto the grid and the bounded palette and enter the atlas only as a four-level luminance map on each species' plain body pixels, mapped onto the ramp of whatever frame is drawn (intact, molt, angry). AI output never replaces an authored outline, so every frame stays readable at phone size and in palette.

| `art/workflows/sprites/variant-qwen-edit.json` | ComfyUI API workflow: Qwen-Image-Edit-2511 fp8 + Lightning 4-step LoRA; keyframe (`$input`) → molt variant |

### Rerun

A Python venv with Pillow, NumPy and SciPy (`python3 -m venv <dir> && <dir>/bin/pip install pillow numpy scipy`; keep it outside `/home/forge/src`, which is a small shared tmpfs), then:

```bash
python tools/sprite_pipeline.py offline     # finish -> atlases -> sheets; no GPU, byte-identical output
python tools/sprite_pipeline.py all         # keyframes -> edits -> finish -> atlases -> sheets
python tools/sprite_pipeline.py keyframes   # or any single stage: edits, finish, atlases, sheets
```

GPU stages post the committed workflows to the project's ComfyUI studio over its HTTP API (`$COMFYUI_URL`, default `http://studio:8188`, the same server `studio.run_workflow` drives) with the seeds and prompts above, so the same models and seeds reproduce the candidates; raw outputs go to `$SPRITE_PIPELINE_CACHE` (default `~/.cache/demon-attack/sprite-pipeline`, never the repo). Agents can run the same workflows through `studio.run_workflow` / `studio.queue_workflow` (`$prompt`/`$seed` overrides, `inputs: {input: <keyframe>}` for edits) and drop the outputs into the cache as `<species>-<seed>.png`. Finishing is CPU-only and deterministic: colour-key matte from the border, largest component, head/torso window (central 34 % of the width, top 80 % of the height), box-sampled onto the body box and quantised to four levels at the 20/55/85 % luminance quantiles.

Stages in detail:

1. **keyframes**: four candidates per species at seed, seed+1, … (prompts.json); pick in `selections.json`.
2. **edits**: three molt variants of the selected keyframe (cracks; cracked with glowing flesh; shattered with broken horn); used as molt detail maps.
3. **finish**: → `detail/<species>.png` and `detail/<species>-m<k>.png`.
4. **atlases**: the four generators. Wing in-betweens are not AI-interpolated: the eight-pose strokes come from the joint-angle tables (`STROKE`, `COCKED`, `DIVE`, … in the generators), which keeps them exactly aligned. Wan2.2 VACE in-betweening was evaluated as unnecessary for that reason and to spare the shared GPU.
5. **sheets**: contact sheets for review.

### Verification

`flutter test` covers atlas sizes, binary alpha, the bounded palette, sentinel pose rules (distinct frames, folding recovery and rush) and wing-cannon alternation. Visual review uses the gallery (`flutter build web -t lib/gallery_main.dart -o <outside-src>/gallery`, served by `preview.publish` from an ignored folder) and host browser screenshots at desktop and phone sizes.
